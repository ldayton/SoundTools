# SoundTools

DoReGo and Soundglow share one npm workspace repository while remaining separate
applications and deployments.

| Directory | Purpose |
| --- | --- |
| `apps/dorego` | Vocal warm-ups, recorded instruments, MIDI/video CLI |
| `apps/soundglow` | Live voice analysis and visual feedback |
| `packages/browser-diagnostics` | Bounded diagnostics and automatic production monitoring |
| `packages/browser-offline` | Common service worker caching and lifecycle runtime |

## Development

Use Node 24. Run `npm ci` at the repository root, then
`npm run build:shared`. Start DoReGo with `npm run dev --workspace=dorego`.
Soundglow's authored browser source lives in `apps/soundglow/dist`; **that directory
is source, not disposable build output**. Its generated static site is `site`.

Edit shared packages directly. Both apps resolve the same workspace source;
there are no vendored npm archives, separate lockfiles, or synchronization scripts.
Soundglow's copies of shared browser scripts are generated by `prepare:shared`.

## Validation

`npm test` builds shared code and runs shared contracts, DoReGo unit/Pages/offline
checks, and Soundglow's core, visual and update suites. Install browsers first with
`npx playwright install chromium firefox webkit`. DoReGo's complete desktop,
lifecycle, Pages and offline matrix is `npm run test:browsers --workspace=dorego`.
GitHub CI runs that matrix and Soundglow's suite on each main push and PR.
For a deployed root-path site, run
`PAGES_TEST_URL=https://do-re-go.vercel.app/ npm run test:pages --workspace=dorego`
and `node scripts/smoke-soundglow.cjs https://soundglow.vercel.app/`.
The latter checks real WASM analysis and recorded-speech playback after an offline
reload, as well as immutable asset headers and MIME types.

`npm run build:dorego` and `npm run build:soundglow` produce root-path Vercel
static sites. Original piano recordings stay in Git for local CLI use; DoReGo's
web deployment includes only the compressed browser recordings.

## Git history

Both original repositories are imported without rewriting their commits. The
import merges preserve original commit IDs; follow history through those parents
when looking before the move. `scripts/history.json` records the original tips,
and `npm run verify:history` checks they remain ancestors. Original checkouts and
GitHub repositories are retained. Local work present during migration was captured
in separate snapshot commits before restructuring.

## Vercel

Production: [DoReGo](https://do-re-go.vercel.app/) and
[Soundglow](https://soundglow.vercel.app/), in the `team-lily` Vercel account.
Both projects are connected to `ldayton/SoundTools`.

Create separate projects with root directories `apps/dorego` and `apps/soundglow`.
Enable access to source outside each root directory so npm can use the workspace
packages and root lockfile. Each app's `vercel.json` supplies install/build/output
settings. Connect both projects to this repository's main branch for production
and pull requests for previews.

For a project's first deployment, leave `RETAIN_FROM_ORIGIN` unset. After verifying
that deployment, set it to the stable production origin (HTTPS, no path) for future
production and preview builds. Builds fetch the previous `asset-history.json`,
verify retained files by SHA-256, and include immutable assets for the last three
releases and all releases from the past 24 hours. This protects old open tabs and
lazy-loaded engines across deployments. A configured origin that cannot provide
its verified inventory fails the build rather than silently dropping old assets.
Service workers and release inventories use no-store response headers; hashed
assets are immutable. Existing app-specific offline update behavior is preserved.

Moving to a new origin does not migrate browser local storage, offline downloads,
or microphone permissions. The original GitHub Pages sites remain available;
redirects or removal should be a separate decision after deployment validation.
