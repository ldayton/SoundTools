# Native/WASM and visual regression gates

## Routine build (no native Praat required)

```sh
npm ci
npx playwright install chromium
npm run build
```

`build` verifies the vendored WASM/JS hashes, runs core tests and compares the
streaming adapter against the checked-in native fixture, then runs Chromium
canvas snapshots at desktop and mobile Retina dimensions. A failure blocks Pages
deployment. Pull requests also run verification, without deployment permissions.
Generated files, node_modules and reports are ignored; keep `fixtures/`,
`baselines/`, the package lock and engine manifest in Git.

`npm run test:core` and `npm run test:visual` run either group separately.
The replay requires neither a microphone nor audible playback. It exercises the
production PraatStream, acceptFrames and renderer with a deterministic audio
clock. AudioWorklet/capture behavior is covered separately, not by this replay.

## What is fixed

The English PCM fixture is speech 12–22 seconds with extra right context, from
our public-domain LibriVox recording (see dist/audio/CREDITS.txt). Its compressed
bytes and decoded bytes have pinned SHA-256 digests. The native power matrix is
float64, time-major, with explicit dimensions/settings and native binary/version
provenance in `fixtures/reference.json`; it is not generated by WASM.

Both sides use 24 kHz PCM, a 5 ms Gaussian window, a 5 ms hop, requested frequency
spacing 10 Hz (actual 23.4375 Hz), 0–5 kHz, 70 dB range, autoscaling and
6 dB/octave pre-emphasis, with no compression. The check asserts all 2000 frame
timestamps, metadata, 213 bins, finite/nonnegative values, relative RMS error
and maximum individual-cell error across 426000 cells. A matching hop alone is
insufficient: Praat's finite-block centering can shift the first frame by half a
hop. The stored first-frame time is checked too.

The fixture's measured relative RMS error was 2.57e-8. Both RMS and peak-relative
maximum error limits are 1e-6 (plus a 1e-12 absolute floor for the latter), allowing
float32 output rounding while rejecting materially different analysis.

## Screenshot baseline policy

Playwright 1.64.1 and its bundled Chromium are pinned by package-lock.json.
Desktop is 671×867 at DPR 1; mobile is 390×844 at DPR 2. Replay waits for fonts
and layout before rendering and publishes a completion/failure signal. Tests
check metadata, full history coverage and a non-blank spectrum before capturing.

The PNG is the raw spectrogram canvas, excluding OS fonts, axes and HTML legend
layers. Comparison permits perceptual threshold 0.08 on at most 0.1% of pixels;
it catches substantive palette, geometry and interpolation changes. It does not
assert pixel equivalence with native Praat's grayscale renderer.

Snapshots were generated and reviewed locally on macOS. CI uses Ubuntu 24.04.
The replay fixes canvas dimensions (629×739 and 748×1414 physical pixels) so
platform font metrics in surrounding controls cannot change the signal plot.
Do not loosen tolerances or automatically replace baselines to make CI pass.

## Failure evidence

`test-results/assets.json` records asset integrity. `test-results/numeric/`
contains the numerical error report, reference metadata and actual powers on
numerical failure. Playwright saves replay metadata, actual PNG, expected/actual/
diff images on mismatch, failure screenshot, trace and HTML report. GitHub Actions
uploads `test-results/` and `playwright-report/` even on failure (7 days).
Missing baselines fail; CI never regenerates native expectations or approves images.

## Deliberate updates

For an intentional renderer change:

```sh
npm run test:visual:update
```

Review both desktop and mobile PNGs, then run `npm run build` normally. Screenshot
updates are independent of native numerical references.

For an intentional engine/reference change, using a separately reviewed native
Praat binary (not the WASM package under test):

```sh
python3 tests/visual/prepare.py --praat /path/to/Praat.app/Contents/MacOS/Praat
python3 tests/visual/freeze-reference.py --praat /path/to/Praat.app/Contents/MacOS/Praat
npm run build
```

Review native provenance, settings and fixture hashes alongside the engine
update. These commands are maintainer actions and never run in routine CI.
The native image in generated/ is available for a separate grayscale comparison.
